# Publish to Notion (Stage 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Stage 7 (`publish`) of the 7-stage *Das Parfum* pipeline, publishing rendered Sektion tables to a private Notion workspace as child pages under a parent page, tracked by `data/output/published.json` for idempotent resumption.

**Architecture:**
- `src/parfum/notion.py`: Pure payload builder constructing 2-column Notion `table` blocks with italicized German cells; `NotionClient` using an injectable HTTP transport, handling rate limits and exponential backoff on 429/5xx.
- `src/parfum/publish.py`: Stage 7 orchestrator managing `data/output/published.json` mapping `sektion_id -> {page_id, content_hash}`. Skips unmodified sections; updates on force/change.
- `src/parfum/cli.py`: Wire `parfum publish [--scope SCOPE] [--force] [--dry-run]` into the CLI.

**Tech Stack:** Python 3.12 (pinned via `uv`), `httpx`, pytest.

**Spec:** `docs/superpowers/specs/2026-09-15-parfum-interlinear-design.md` (§1, §3.1, §6.3, §8)

---

## Global Constraints

- **Python 3.12, not the system 3.14.** `uv` pins it.
- **The book text is copyrighted and is never committed.** Book text flows disk-to-disk through files and network calls. Never dump full raw book text into chat.
- **Tests never touch the wire.** `NotionClient` uses an injectable transport so all unit and integration tests run offline against recorded or mock responses. Live calls require `PARFUM_LIVE=1` and `NOTION_API_KEY`.
- **Idempotence is strict:** Re-running `parfum publish` on an already published book does 0 network writes and changes nothing.
